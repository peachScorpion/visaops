订单与资金字段规格

按众信现有系统的结构重新梳理：订单列表沿用飞猪销售管理那套「汇总条 + 订单元信息行 + 分段主体 + 操作行」的四层骨架； 收款 / 退款 / 转款三张财务单沿用众信财务管理 · 业务资金管理的字段与审核页签。 UOM 与 CSP 保持两套视图，差异只在可见字段与可执行动作，底层是同一张订单。

一、信息骨架：一张订单四层

现在的列表是「一行七列」，金额、状态、进度挤在同一水平线上，看不出主次。 改成四层后，订单级元信息（谁卖的、什么时候、哪个渠道）单独占一条，业务主体按语义分段，操作独占一行。

L0汇总条 · 当前筛选结果的合计

横排一条，不再用六张大 KPI 卡（占掉将近一屏，翻订单要滚两次）。口径＝当前筛选条件命中的全部订单，不是当前页。

L1订单元信息行 · 这张单的身份

订单号、下单时间、销售渠道、销售公司、销售人员、建单人、查看详情。飞猪把保险状态 / 合同状态也放在这层——签证业务对应的是合同状态与资料收件状态。

L2业务主体 · 分段展示

客户、产品、金额（应收 / 实收 / 结算毛利三段）、状态各占一段，段内纵向排列「标签 + 值」，段间靠留白分隔而不是竖线。

L3操作行 · 右对齐独占一行

按订单当前状态只给可执行的动作，不可执行的不显示（不用置灰堆一排）。主操作一个，橙色实心。

三、CSP 门店工作台 · 订单列表

使用人：门店销售、同业代理。只看本门店 / 本渠道的单，看得到结算价与毛利（要算提成）， 但看不到平台应付账款口径的字段，也不能改价、不能放行资金。

CSP 相比 UOM，去掉这些
  • 待付供应商——平台对供应商的应付账款，门店不参与结算
  • 已开票——开票由集团财务统一处理，门店只发起
  • 建单人 / 销售公司——本店内部，销售人员一个字段够了
  • 调价、派单、确认收款三个动作全部不可执行
CSP 相比 UOM，多这些
  • 逐人办签进度——门店直接对客，客人问「我的签证办到哪了」要能一眼答上
  • 代客支付主操作——CSP 的核心动作
  • 资料收件状态提到 L1——门店负责收客人材料，这是它每天的待办
  • 汇总条口径是本店，不含其它门店
CSP 保留结算价与毛利，不隐藏。理由：门店提成按毛利算，藏了销售没法判断值不值得卖； 而且 8/27 定的产品详情页已经在显示「结算价 / 最高毛利」，列表藏起来反而不一致。 但供应商名称在列表层不显示——产品详情页的「供应商比价」里已经有，列表里再挂一遍容易诱导门店绕过平台直连。这条你如果不同意，我加回来只是一行的事。

四、状态口径：三条互不替代的线

飞猪那张单同时挂着「订单状态 / 保险状态 / 合同状态 / 运营平台已支付 / 供应商已确认」，是因为它们互相不能推导。签证业务同理，需要三条独立状态线，不能压成一个字段。

状态线取值谁改它跟其它线的关系
① 订单状态 待付款 → 已付款 → 办理中 → 已完成 ／ 退款中 · 已退款 · 已取消 系统按付款、放行、办签结果自动流转 总状态，对客对外只说这一条
② 资金闸门未放行 / 已放行 只有 UOM 财务能改，CSP 只读 放行是「已付款 → 办理中」的唯一触发条件，放行后不可撤销
③ 签证办理进度
按办签人各自独立		 待收材料 → 材料审核 → 补料中 → 填表缴费 → 预约中 → 已递交 → 已出结果 → 已返还 UOM 专员操作，CSP 只读 同一订单多个办签人各走各的；全部到「已返还」订单才算已完成
④ 合同状态未签约 / 已签约 / 免签约CSP 发起，客户签署独立，不阻塞办理
⑤ 资料收件状态未收件 / 部分收件 / 已收齐CSP 或客户上传后自动判定影响 ③ 能否从「待收材料」往下走
她 8/21 提过「25 个状态太多了」。这里没有增加状态总数，是把原来混在一条线上的值拆到 5 条线： 每条线单独看都只有 2–8 个取值，列表上一次最多展示 3 条（订单 / 资金 / 办签），其余进详情页。

五、财务三单：收款 / 退款 / 转款

字段与页签直接沿用众信「财务管理 › 业务资金管理」。UOM 侧是操作台（要审核、要生成凭证），CSP 侧是同一张表的只读视图，门店只查自己的单、只能打印收据。

共用页签 三张单一致

全部 待审核 已审核 待生成凭证 已生成凭证 有误  — CSP 侧只保留 全部 / 待审核 / 已审核 三个，凭证与差错是财务内部流程。

签证业务的退款有一条旅游团单没有的规则：已递交使领馆之后拒签，签证费不可退，只退服务费。 所以退款单要拆「可退部分 / 不可退部分」两个金额，而不是一个退款金额。这条我按拒签退款保障套餐的口径写进去，非保障套餐的具体退款比例得你给业务口径——我不猜。
