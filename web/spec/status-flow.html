2026-08-31 再改：三条线在页面上也彻底分开了。唐美芳：「订单管理的状态流转还是有问题，之前不是说就5个么，你怎么还是把订单状态与签证办理状态混在一起了」。 四端（UOM / CSP / UBK / C 端）的订单列表页签一律只放订单状态那 5 个值； 原来混在页签里的「待财务放行」「待收材料」「办理中」「已出签待返还」全部降级成可叠加的筛选项—— 它们与订单状态并不互斥，一张「已付款」的单同时就是「待收材料」，做成并排页签会让每个页签都查不全。 列表里「办签」那一格也只放办签进度：退出的人显示「已退出」而不是「已退款」， 未付款与已取消的订单整格给「—」（还没进入办签流程）。

2026-08-31 改：订单状态去掉了「办理中」（唐美芳：「订单状态里很少有办理中这种中间态的」）， 回到 5 个值只管钱；「办理中」改成由办签人进度派生的办理状态，不落库不用人维护； 资金闸门降级成风险提示标签（只在待放行时出现，带问号说明），不再当状态线展示。

闸门 1 · 付款：客户或门店付款 → 自动生成收款单 SK/S…，订单进「已付款」。此时办签进度仍锁在 P1，专员看不到这张单。
闸门 2 · 财务放行（唯一的关键闸门）：财务审核收款单并确认放行 → gate=1 → 系统立即生成签证工单、按套餐时效设 SLA、对供应商挂应付。订单状态仍是「已付款」，办理状态转「办理中」，办签进度这才允许从 P1 往下走。放行不可撤销。
闸门 3 · 全员交付：订单下所有办签人都走到 P10「已交付客户」→ 订单才转「已完成」。只要有一人没到，订单停在「已付款」，办理状态显示「办理中」。（原文这里写的是「订单停在办理中」——「办理中」不是订单状态，2026-08-31 改。）

分支：拒签与退款

场景流转
拒签（P9 出结果为拒签）办签人 state=refunded，订单转「已退款」。已递交使领馆的签证费不可退，只退服务费——非「拒签退款保障」套餐的具体退款比例还等你给口径，现在按全额服务费退算。
放行前取消订单转「已取消」，收款单原路退回，办签进度停在 P1，不产生工单，不对供应商挂应付。
放行后取消必须走退款单：发起 → 主管审批 → 财务出账。工单同步关闭，已产生的供应商应付按实际进度结算。
客户改期走转款单：原单款项转入新单，财务审核通过前钱冻结在原单，两边都不能用。
刚修掉一处真实矛盾：原来有 3 张订单资金未放行（VS-26080001 / VS-26080002 / VS-26080016）， 办签人却已经推进到 P4「表单填写中」——违反了闸门 2 的规则，验收时会看到自相矛盾的状态。已全部锁回 P1。
