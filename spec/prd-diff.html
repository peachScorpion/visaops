对照凯撒签证 PRD · 流程差异

对照件：《通通游-签证 需求规格说明书 V1.0》（张薇薇，2018-07-31，已在凯撒落地）。 只对照流程部分：3.5 业务流程图、4.8 供应商订单管理与客人办理进度维护、4.13 运营 B 平台订单管理、 4.14.4/4.14.7 H5 订单填写与退款。产品配置、渠道投放、首页运营那几章不在本次范围。

口径：PRD 是 2018 年的，DS-160 填表在那时是线下动作，没有进系统；我们这版把它显性化成一个节点 并加了 AI 代填，属于升级不算差异。凡是「我们比 PRD 多」且能说清业务理由的，按升级处理； 凡是「PRD 有而我们没有」或「我们把 PRD 分开的东西合并了」，才算差异。

签证办理状态的映射：PRD 6 步 → 我们 10 步

二、对上了的（已实测，不用改）

已符合跳跃推进时自动补齐中间环节

PRD 4.8.3 原文：「复选框跳跃进行钩选时，需将中间环节默认选中」。 系统 set_progress() 已按这条实现。实测：把一位办签人从 P2 直接推到 P7， 返回 auto_filled: ["材料已齐备","表单填写中","待预约面签","已预约待面签"]， 操作日志里也留了「自动补齐」记录。

已符合全员到终点 → 订单自动转已完成

PRD：「全部办签人的签证办理状态为资料返还，订单办理状态为已完成」+「订单办理状态为已完成时， 订单状态变更为已完成」。系统 sync_order() 同口径，且只统计 state='normal' 的办签人 （已退单的不参与判定，这点 PRD 没写死，但业务上必须这样，否则一人退单整单永远完不成）。 实测：把单人单的办签人推到 P10，订单状态即刻从「办理中」变「已完成」。

已符合签证结果三选一含撤签、资料返还带快递单号

PRD：「反馈签证结果，单选（必填）：出签、拒签、撤签」「资料返还，可维护快递公司和快递单号」。 系统结果下拉是四选一（出签 / 拒签 / 撤签 / 行政审查）——多一个「行政审查」是美签的真实状态， PRD 时代按拒签处理，实际上它既不是出签也不是拒签，会挂几周到几个月，必须单列。 资料返还的 deliver 表有快递公司与快递单号，另加了电子签收。

已符合办签人状态、退款流程

客人状态「正常 / 退单」＝我们的 normal / refunded。 退款 PRD 只有「退款中 / 退款完成」两态，我们拆成申请 → 主管审批 → 财务出账 → 已驳回四态—— PRD 那版退款审核是一步，我们按众信的实际审批链拆开了，属于细化不是缺失。

三、这次直接改掉的（已上线 v175）

已修订单详情缺「收货人信息」

PRD 4.8.2 与 4.13.3 都明确要求订单详情同时列订单联系人与收货人（收货人、联系电话、收货地址）。 我们原来只有联系人。签证办完要把护照原件寄回客户，收货地址是履约必需信息，漏了这块专员没法安排返还。 现在「联系人信息」页签下多了一块「收货人信息（资料返还）」，没填地址的显示「资料返还前需补充」。

已修办签人列表缺「证件签发地」与「国籍」

PRD 4.8.2 列的办签人字段是：中文姓名、手机号、英文姓/名、性别、出生日期、证件类型、证件号码、 证件有效期、证件签发地、国籍。后两个我们库里有（id_place / nation） 但订单详情页没展示。这两个字段在送签时要填进申请表，专员核对时看不到就得去点每个人的档案。已补进办签人表。

已修撤签没有说明文本框

PRD：「拒签和撤签显示文本框可维护说明」。我们原来只有「拒签说明」，撤签没地方写原因。 已改成「拒签 / 撤签说明」，提示语写明撤签要填撤回原因与客户确认情况。

四、要你拍板的（都是结构性的，我没擅自改）

差异 1订单状态里混进了「办理中」——这是我认为你说的「不对劲」的根源

PRD：两个字段并列
订单状态＝已付款（钱走到哪了）
订单办理状态＝办理中（活干到哪了）
两条线各管一件事，可以任意组合筛选
我们：压成一个字段
订单状态＝办理中
「已付款」和「办理中」变成互斥的两个值， 一张单不可能既是已付款又是办理中

后果很具体：一张已付款、财务已放行、但三个办签人全都还停在「待收材料」的单， 在我们系统里叫「办理中」——可它一步都没办。财务想筛「已付款的单」筛不出它， 运营想筛「真正在办的单」也筛不掉它。现在只能靠「资金闸门」这个内部字段勉强区分， 列表上要挂两个标签才说得清一件事。

我的建议：按 PRD 拆成两个字段。订单状态回到 5 个值（待付款/已付款/已完成/已取消/已退款）， 另加一个派生的「订单办理状态」（未开始/办理中/已完成），由办签人进度自动算，不用人维护。 改动面：订单列表、订单详情、CSP/UBK 两端列表的状态列与页签，以及 sync_order() 的判定， 估计半天。要不要改，你定。

差异 2免面签的产品也会走「待预约面签 / 已预约待面签」两步

PRD 4.8.3：「产品属性中有面试/录指纹显示此按钮，否则隐藏」——预约是按产品属性条件出现的。 我们的 P1–P10 是一条固定链路，日本、新加坡这类免面签产品也要经过 P5、P6， 专员只能一路点过去，等于两个空转节点。

我的建议：进度链路按产品属性动态生成——need_interview=0 的产品跳过 P5/P6， P4 之后直接进 P7。这样免面签产品是 8 步，需面签的是 10 步。 但这会让「进度百分比」在不同产品间不可比（8 步的第 5 步 vs 10 步的第 5 步不是一回事）， 报表口径要一起调。改还是不改，你定。

差异 3缺独立的「支付状态」筛选

PRD 4.13.1 运营端订单列表有独立的「支付状态（待支付/支付完成）」筛选项，与订单状态并列。 我们没有这个字段，要判断有没有付款得看订单状态是不是 created。 如果差异 1 按 PRD 拆开了，支付状态可以顺带一起加；如果差异 1 不改，单加这个意义不大。 建议跟差异 1 一起定。

差异 4PRD 有「佣金信息」，我们没有

PRD 4.13.3 订单详情列了佣金块：供应商名称、供应商结算价、分销商名称、分销商收益、 分销员名称、分销员收益。我们只有供应商结算价与平台毛利，没有分销商 / 分销员两层收益。

你 8/19 定过「本期不涉及分销分润与返佣」，所以我按不做处理，在这里列出来只是让你知道 PRD 里有这块、我不是漏看了。哪天要做分销体系，这是现成的字段清单。
