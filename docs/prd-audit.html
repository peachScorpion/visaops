一、逐节对照 PRD 第 4 章 · 14 节

PRD 章节结论VisaOps 现状与差异
4.1 运维-样例模版管理部分 数据模型 sample_tpl 与运维端「样例模版库」列表、查看已具备，完整版条目可引用样例。缺：新增／修改样例、多文件上传与重名校验。
4.2 运维-完整版管理部分 字段已按 PRD 逐项落地：资料属性（原件／复印件）、提供方式（邮寄自送／电子上传／面试携带）、份数、提交必要性（必须／建议）、资料提交要求、关联样例、适用人群五类、生效日期。查看页支持按人群实时裁剪清单。缺：新增／编辑／复制完整版、六位随机版本号生成、发布状态、「已被哪些产品关联」回显、改生效日期时自动派生新版本号。
4.3 运维-产品管理部分 字段齐备（受理范围、受理说明、有效期天／年、入境次数、停留天数、是否面试、是否录指纹、关联完整版、发布状态）。缺：新增／编辑产品、取消发布、国家—签证类型—送签地二级联动检索。
4.4 供应商-地址管理未覆盖 地址表已建且被产品与资料返还链路引用（订单详情展示原件邮寄地址），但无地址管理页面与增删改接口，当前仅靠初始化数据。
4.5 供应商-产品管理（报价）部分 供应商产品、套餐（签证费＋服务费＝基础结算价、零售参考价、办理时长、预订须知）与改价已可用，改价后自动重算各渠道投放价并触发预警。缺：三步新增流程（选未报价平台产品 → 确认／改写完整版 → 报价发布）、自有完整版派生、发布时「投放全部渠道组／暂存产品库」二选一。
4.6 供应商-渠道组管理未覆盖 渠道组与加价规则的数据模型已完整（国家范围、加价基础＝基础结算价／服务费、加价方式＝原价／百分比／固定金额），投放计算已按规则执行，但无渠道组的新增、编辑、成员维护界面。
4.7 供应商-渠道组投放部分 投放明细、按策略计算的渠道结算价、报价预警（结算价高于零售价）已实现。缺：已投放／未投放双列表切换、一键投放、批量投放、投放价格调整弹窗（渠道结算价与渠道建议结算价可改）。
4.8 供应商-订单管理已覆盖 接单工作台、订单详情、办理进度维护均已实现，且强于 PRD：进度由 PRD 的六档细化为十步并支持跳步自动补齐中间环节；订单办理状态按「全部办签人到达资料返还」自动置为已完成。增强：客户姓名、手机号、机构名对供应商全量打码。缺：护照号检索。
4.9 运营B-产品管理（代理策略）未覆盖 「按供应商＋国家范围自动决定哪些产品进入可售库」这一策略层尚未建设。注意：此项属于供货可售范围控制，不等同于分销分润，不在本期已排除范围内。
4.10 运营B-我的产品（我的产品／市场产品）未覆盖 代理产品／市场产品双列表、实际零售价维护、收益与收益率计算、套餐级代理与取消代理均未建设。chan_pub 已预留 retail_price、agented 字段，具备承接条件。
4.11 运营B-收货地址管理部分 下单时可选收货地址、资料返还按该地址寄回已通；缺：运营端按客户查看与维护其地址簿。
4.12 运营B-手机端首页配置本期外 轮播图、热门国家九宫格、热门产品五位的运营位配置未建设。属于 C 端流量运营位，与本期「跑通美签作业链路」的验收目标无关，建议后置。
4.13 运营B-订单管理已覆盖 订单总览、待退款订单、订单详情（基本信息／联系人／收货人／办签人明细／交易信息／退款信息／办签信息）均已实现。佣金信息按您的口径本期不做。增强：退款金额由规则引擎按进度节点自动测算，非人工填数。
4.14 H5 签证频道部分 选品、详情（基本信息／按人群切换的所需材料／套餐展开／办理流程）、下单填写、订单列表、订单详情、办理进度查询、退款申请均已实现。缺：城市定位、国家首字母索引搜索、常住地筛选、综合排序与价格排序、条件筛选、常旅客库、材料清单发送至邮箱、申请发票、删除订单。
结论口径：「已覆盖」指核心规则与字段均已落地并可实际操作；「部分」指数据模型与读取链路已通、缺维护端或次要交互；「未覆盖」指该模块尚未建设。

二、VisaOps 超出 PRD 的增量能力 凯撒 V1.0 未涉及

  1. 资金闸门：财务确认收款前不派单，操作专员与供应商完全不可见该笔业务，杜绝未收款先作业。
  2. 工单制作业：按办签人拆工单并轮转派工，主管侧可见人均负载并支持改派。
  3. 补料单闭环：驳回材料自动打包成补料单、七天倒计时、材料全部通过后自动关单。
  4. 退款规则引擎：按进度节点自动测算应退金额，区分拒签退款保障、公司责任、客户责任。
  5. 行政审查跟踪：结果回填为行政审查时自动生成十五天到期提醒。
  6. 送签批次：多张工单并批送签，批次号贯穿全链路。
  7. 垫付与缴费台账：签证费垫付、供应商应付挂账与结算对账分账管理。
  8. 全链路事件留痕：每一次状态变更记录操作人、时间、动作与单号，可追溯。
  9. 管理端隐私打码：姓名、手机号、机构名在所有非本人视角一律脱敏。

三、建议的补齐顺序

  1. 第一优先｜供应商上架链路：地址管理、渠道组管理、供应商新增产品三步报价、投放批量操作与价格调整。理由：这是「先上产品」的前置动作，不补齐则新国家、新供应商无法自助上线。
  2. 第二优先｜运维配置链路：样例模版、完整版、平台产品的新增与编辑，含版本号派生与发布控制。理由：材料清单是签证业务的核心资产，目前只能读不能改。
  3. 第三优先｜运营可售与售价：代理策略、我的产品／市场产品双列表、实际零售价与收益率。
  4. 第四优先｜C 端体验项：定位、排序、筛选、常旅客、清单发邮箱、发票。
  5. 建议后置：手机端首页运营位配置。
